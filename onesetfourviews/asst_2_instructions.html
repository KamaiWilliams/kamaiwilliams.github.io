A "dataset" is a collection of related records: restaurants, artworks, inspections, bus stops. In this project you will work with a slice of real public data, Prince George's County food safety inspections, saved in your starter code as a .json file. You will load it with fetch() and show it four different ways: three ordinary views, and one view of charts made with an external library.

The same information tells different stories depending on how it is presented. Information architecture is what we call the choice of what each view emphasises or hides.

Learning Objectives

By completing this project, you will demonstrate that you can:

  • Load data asynchronously with fetch() and async/await
  • Transform data with array methods: reshape it into what each view, and each library, needs
  • Include an external library from a CDN and pass it your data
  • Design several interface patterns for different user goals
  • Make your views usable by more people by correctly using real tables, labelled charts, and text alternatives.

Starter Code

Download the starter code: asst_2_restaurants.zip

The starter code provides:

  • One complete example view (Card View) showing the pattern to follow
  • A stylesheet with utility classes
  • Data loading, view switching and error display, already wired up
  • Incomplete view functions for you to write, in the editable_js/ folder
  • data.json: 150 recent food safety inspections from Prince George's County

To run it: open the folder in VS Code and start Live Server. Opening index.html by double-clicking it will not work: browsers block fetch() from a file on your own computer. It will also work once it is on GitHub Pages.

1. The Dataset

Everyone works with the same data: 150 recent food safety inspections from Prince George's County Open Data, in data.json. Each record is one inspection of one business. Open the file in VS Code and read a few records before you write any code.

Useful fields:

  • name, category (Restaurant, Carry-out, Fast Food - Chain…), address_line_1, city, zip
  • inspection_date and inspection_type
  • inspection_results (Compliant - No Health Risk, Critical Violations observed…)
  • 15 food safety checks, such as proper_hand_washing and cold_holding_temperature, each either "In Compliance" or "Out of Compliance"

Missing values are written as "------" or "N/A", not left empty. Your code won't break on them: it will just show ------ or N/A on the page. Treat both as missing.

There are no ready-made numbers. You make them by counting: inspections per city, inspections per month, or how many checks in each inspection were "Out of Compliance".

The same inspections can serve very different people: a diner choosing where to eat, a health inspector planning visits, a reporter looking for patterns. Decide who each of your views is for.

2. Load the Data

The starter already loads data.json, in editable_js/load_data.js:

async function loadData() {
  const response = await fetch('./data.json');
  const data = await response.json();
  return data;
}

You don't need to change it. Open the browser console: you should see Loaded 150 items. If you see an error instead, check that you are running Live Server.

3. The Four Views

Card View is done for you as an example. Write the other three. Each view must:

  • Transform the data for its own purpose: don't just print every field
  • Handle missing values (show "Not listed" instead of ------ or N/A). Card View shows one way to do it.
  • Serve a different user goal, and look clearly different from the others
  • Work on a phone and on a laptop

Table View

  • A real HTML <table> with <th> header cells and a <caption> that says what the table shows
  • The 4–6 most useful fields for the person this table is for
  • Optional: sorting. See the sortable table example at the W3C

Category View

  • Group the inspections by one meaningful field (type of business, city, inspection result…)
  • Show how many inspections are in each group, plus one other number per group (how many were compliant, the average number of "Out of Compliance" checks, the most recent inspection)
  • Make the groups easy to compare, and visually distinct from the items inside them

Charts View

This view replaces the old text statistics view. Use Chart.js, included from a CDN with a <script> tag. (If you would rather use another charting library, check with me first.)

  • At least two charts of different types (bar, pie, line, scatter…), each answering a different question about your data
  • Every chart has a title, and every axis has a label
  • Every chart has a text alternative on the page: one sentence that says what the chart shows (for example, "Chain fast food restaurants had the most inspections: 29 of 150"), or a small table of the same numbers. Charts are drawn as pictures, so screen readers can't read them on their own.

Your data → the library's data. Chart.js does not take your array of records. It wants a list of labels and a matching list of numbers. Reshaping your data into that form is the main skill in this view. For example, to count inspections by type of business:

const counts = {};
data.forEach((inspection) => {
  counts[inspection.category] = (counts[inspection.category] || 0) + 1;
});

const labels = Object.keys(counts);    // ['Fast Food - Chain', 'Diet/Nutrition Site', 'Restaurant', ...]
const numbers = Object.values(counts); // [29, 3, 22, ...]

labels and numbers are what you pass to Chart.js. Tutorial 8 walks through this step by step.
